# The banked line says "the findings document" for records banked machine-local

Lands: cross-tool train chunk 282 (record verbs over both layers — the banked and decision lines name the layer)

A delta run interrupted by the host's memory guard after eighty-eight
minutes reported: "87 target(s) committed to the findings document
this run (1233 killed, 244 open among them) ... every committed
target is kept (REQ-exec-cancellation)". The repository document,
`.gomutant/findings.json`, held none of the 87 afterwards: every
record's evidence was unverifiable (an oracle read of the
filesystem root), so each went to the machine-local overlay under
the cache directory, as the layering rules say it should.

The line is true of the overlay and reads as a claim about the
committed document. A reader checking the document, or `git status`,
concludes the run banked nothing. The banked line, and the per-target
commit decision lines, should name the layer each record landed in —
repo or machine-local — and, where every record is machine-local,
say so beside the count, since that is the fact the reader acts on
(the records will not promote, and the next run will not serve them).
